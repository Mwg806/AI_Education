# 智能体开发任务指令
## 一、任务核心目标
基于指定需求文档，采用 LangChain、LangGraph 技术栈开发首个教育领域智能体，整体架构预留多智能体协同扩展能力，全程严格遵循路径边界、运行环境与版本管理规范。

## 二、最高优先级边界约束（必须严格遵守，不得突破）
1. **文件操作边界**：所有代码编写、文件读写、资源引用、项目构建等操作，严格限定在 `/home/mwg/dsj/data/AI_Education` 目录范围内
2. 禁止访问、读取、修改该目录以外的任何文件夹与文件，无额外授权不得突破路径边界

## 三、开发基准与需求依据
1. 本次首个智能体的开发，**必须严格参照文档 `/home/mwg/dsj/data/AI_Education/personalized_learning_planner_agent_national1.md`** 执行
2. 需完整覆盖文档内所有功能定义、业务逻辑、交互流程、输出规范与业务约束，实现专业、可落地、完全符合文档预期的智能体完整代码
3. 所有功能设计不得偏离该文档的需求范围；若进行架构层面的扩展优化，需在满足文档核心需求的前提下开展

## 四、运行环境强制要求
1. 所有代码执行、依赖安装、环境配置与调试运行，必须先激活指定 Conda 虚拟环境：`conda activate Mamba`
2. 项目全部依赖、运行时与调试均基于 Mamba 环境，禁止使用系统全局 Python 或其他虚拟环境
3. 新增第三方依赖需安装至 Mamba 环境内，并同步更新项目依赖清单

## 五、技术栈与工程化规范
1. **核心技术选型**：全程基于 LangChain、LangGraph 技术栈完成智能体（Agent）全流程开发，不得擅自更换核心框架
2. **Prompt Engineering 要求**：
   - 针对智能体角色定位、任务目标、输出格式、边界约束设计体系化提示词
   - 明确指令优先级、输出结构化规则、异常场景处理逻辑，保障模型指令遵循度与输出稳定性
3. **Harness Engineering 要求**：
   - 配套智能体管控机制，覆盖输入校验、输出格式化、异常兜底、错误重试、流程节点校验等能力
   - 确保模型调用全链路可控、运行稳定，有效降低异常输出概率
4. 代码遵循 Python 工程化规范，模块拆分清晰，保留完整注释与可维护性

## 六、多智能体协同架构扩展要求
1. 当前阶段优先完成**第1个智能体（个性化学习规划智能体）**的可运行完整版本
2. 整体框架必须面向多智能体协同场景设计，预留至少支持 6 个及以上智能体协同运行的扩展能力：
   - 定义标准化智能体接口规范：统一输入输出格式、消息协议、调用方式与全局状态结构
   - 设计多智能体协同核心调度层：包含任务分发、信息交互总线、结果聚合、全局状态同步逻辑
   - 保证后续新增智能体可通过标准接口无缝接入，无需重构核心调度框架
3. 首个智能体需严格遵循统一接口规范开发，作为后续多智能体接入的标准范例

## 七、Git 版本管理规则
1. 全程使用 Git 进行代码版本管理，仓库根目录设置在指定工作目录内
2. 按功能模块划分独立开发分支，不同功能点对应不同 Git 分支（如基础框架分支、首个智能体功能分支、多智能体调度分支等）
3. 单功能开发/修改完成并验证通过后，及时提交代码并推送至远程仓库

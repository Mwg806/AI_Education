# 架构说明

## 设计边界

系统遵循“LLM 理解和解释，确定性工具处理事实与计算”的边界。模型不能发布政策事实、计算掌握度、决定选科合法性或覆盖计划版本。模型不可用时，图流程继续走结构化表单和规则服务。

首次规划图：

```text
AgentRequest
  → 请求分派
  → 政策解析与校验
  → 解析 1–6 个科目目标/追问
  → 逐科读取客观诊断证据并建立独立画像
  → 在统一周容量内分配逐科预算（每科最低 60 分钟）
  → 多科候选任务交错生成与周内排期
  → 四类发布校验
  → 等待用户确认
  → 新版本正式发布
```

多科规划继续生成一份统一计划，但每个科目保留独立目标、教材范围、学情画像、时间预算和任务归因。解释模型必须逐科引用对应的 `knowledge_profiles_by_subject`，不能跨科套用掌握度或薄弱点。四类发布校验包括政策与选科、知识覆盖与前置、时间容量与缓冲、内容资源与完成标准，并额外确认全部目标科目均有排期且每科都包含间隔复习、限时训练和阶段测评。任一硬约束失败时，计划停留在草稿或进入人工复核。

快速诊断的命题链路不直接把章节名称交给模型自由发挥：`DiagnosticKnowledgeRetriever` 先从本地 FTS 索引检索 A/B 级课程标准、知识分类与评价框架，服务再建立十个确定性槽位。模型输出必须逐题回传槽位、章节、知识片段 ID 和逐字原文摘录；服务端验证引用确实属于该章节检索结果、摘录确实存在于原文，并继续执行十题、五维各两题和范围覆盖校验。失败时携带校验反馈重新生成，三次仍不合格才进入严格范围匹配的真题兜底。兜底前由 `DiagnosticScopeResolver` 去除“必修第一册/第几章”等目录噪声，将“集合与常用逻辑用语”等复合章名拆为概念，并映射到统一知识分类模块；`QuickDiagnosticBank` 再用章节概念、模块主题、真题知识标签和题干进行加权交叉核验，响应保留实际匹配词与模块 ID。它不会再用固定 2–8 字长串做一次性包含判断，也不会用无关同学科题目凑数。模型引用字段和正确答案在提交前不会暴露给学生，提交后解析保留知识依据和来源元数据。

## 多智能体协作

```text
CollaborationRequest
  → DAG 与循环依赖校验
  → 根据角色或意图路由
  → 同一依赖层受控并发执行
  → 消息总线记录命令与结果
  → 统一结果聚合与证据去重
  → 乐观并发同步全局状态
  → CollaborationResponse
```

新增 Agent 只需：

1. 继承 `BaseEducationAgent`；
2. 声明 `AgentMetadata`、能力和意图；
3. 实现 `ainvoke(AgentRequest) -> AgentResponse`；
4. 注册到 `AgentRegistry`。

调度器没有固定 Agent 数量上限，测试使用 7 个 Agent 验证接入无需改动调度框架。

## 状态与版本

- 所有 Agent 和工具消息携带请求、追踪、学生、操作者和数据版本；
- 写操作使用幂等键；
- 计划确认或调整总是创建新版本；
- `GlobalStateStore` 使用 compare-and-swap 防止协作结果丢失更新；
- 消息总线保留按 trace 查询的不可变消息副本；
- 内存仓库是参考适配器，生产部署应替换为事务数据库和持久事件总线，接口无需修改。

## 安全和隐私

- Pydantic 信任边界拒绝未知字段；
- 密钥只从环境变量读取，`.gitignore` 排除本地配置和密钥文件；
- 错误响应不返回堆栈或凭据；
- 未知政策进入人工复核，不用模型猜测；
- 主观题、内容生成、讲解和生涯规划交给对应专业 Agent；
- 当前参考仓库不采集学习规划之外的个人信息。

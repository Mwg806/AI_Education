# 架构说明

## 设计边界

系统遵循“LLM 理解和解释，确定性工具处理事实与计算”的边界。模型不能发布政策事实、计算掌握度、决定选科合法性或覆盖计划版本。模型不可用时，图流程继续走结构化表单和规则服务。

首次规划图：

```text
AgentRequest
  → 请求分派
  → 政策解析与校验
  → 解析 1–6 个科目目标/追问
  → 逐科读取客观诊断证据并建立独立画像
  → 在统一周容量内分配逐科预算（每科最低 60 分钟）
  → 多科候选任务交错生成与周内排期
  → 四类发布校验
  → 等待用户确认
  → 新版本正式发布
```

多科规划继续生成一份统一计划，但每个科目保留独立目标、教材范围、学情画像、逐题诊断事实、时间预算和任务归因。解释模型必须逐科引用对应的 `knowledge_profiles_by_subject` 与 `diagnostic_attempts_by_subject`，不能跨科套用答案、用时、掌握度或薄弱点。四类发布校验包括政策与选科、知识覆盖与前置、时间容量与缓冲、内容资源与完成标准，并额外确认全部目标科目均有排期且每科都包含间隔复习、限时训练和阶段测评。任一硬约束失败时，计划停留在草稿或进入人工复核。

快速诊断采用“离线题源处理、服务端组卷、确定性评分、AI 规划”的职责分离。`DiagnosticService` 不调用模型命题，而是让 `DiagnosticScopeResolver` 去除教材分册和章序噪声、拆分复合章名并映射统一知识分类，再由 `QuickDiagnosticBank` 按章节概念、模块主题、题目标签和题干选取 10 题。生产环境的补充题库由 `scripts/build_oss_quick_diagnostic_bank.py` 从私有 OSS 原始 DOCX 逐对象流式读取，只接收来源文档中能够严格配对“四选一题干—标准答案”、不依赖缺失图片或公式的题目；输出为 `knowledge/processed/quick_diagnostic/v1/subjects/*.json.gz`，并最后发布带题量和 SHA-256 的 `manifest.json`。

在线请求只通过 `StructuredOssQuickDiagnosticBank` 获取压缩后的结构化分片，使用 ECS 实例 RAM 角色的短期凭据，不保存 AccessKey。分片在进入组卷器前必须通过前缀边界、压缩/解压大小、JSON schema、学科、题量、唯一来源 ID、四选项、答案下标和 SHA-256 校验。通过校验的最近版本以 `0700/0600` 权限写入 ECS 小型缓存；OSS 异常时先用最近校验缓存，再回退仓库内高考真题，原始题源不进入在线路径。严格范围题量充足时响应标记 `selected_scope`；不足时改用本学科综合核验题库并明确标记 `subject_bank` 和“未严格匹配”，不会伪造章节依据，也不会阻断学生完成诊断。正确答案和解析在提交前始终隐藏。

提交后服务端执行确定性评分，并把证据细化到“章节＋知识点＋基础/应用”，避免同一章节的全部题被聚合成两个粗粒度状态。同时生成 `diagnostic_attempts_by_subject` 逐题事实包，包含题干、四个选项、学生答案、正确答案、对错、难度、实际/建议用时、置信度及本地来源。确定性计划引擎用细粒度知识画像安排任务，解释模型逐科读取事实包说明安排依据；提示约束要求错题存在时引用具体知识点，区分单次观察与稳定结论，禁止编造答案、用时、薄弱点或从一次作答推断性格、心理和长期学习态度。计划的 `generation_basis` 记录实际采用的诊断科目数和逐题证据数，便于审计。

## 多智能体协作

```text
CollaborationRequest
  → DAG 与循环依赖校验
  → 根据角色或意图路由
  → 同一依赖层受控并发执行
  → 消息总线记录命令与结果
  → 统一结果聚合与证据去重
  → 乐观并发同步全局状态
  → CollaborationResponse
```

新增 Agent 只需：

1. 继承 `BaseEducationAgent`；
2. 声明 `AgentMetadata`、能力和意图；
3. 实现 `ainvoke(AgentRequest) -> AgentResponse`；
4. 注册到 `AgentRegistry`。

调度器没有固定 Agent 数量上限，测试使用 7 个 Agent 验证接入无需改动调度框架。

## 状态与版本

- 所有 Agent 和工具消息携带请求、追踪、学生、操作者和数据版本；
- 写操作使用幂等键；
- 计划确认或调整总是创建新版本；
- `GlobalStateStore` 使用 compare-and-swap 防止协作结果丢失更新；
- 消息总线保留按 trace 查询的不可变消息副本；
- 内存仓库是参考适配器，生产部署应替换为事务数据库和持久事件总线，接口无需修改。

## 安全和隐私

- Pydantic 信任边界拒绝未知字段；
- 密钥只从环境变量读取，`.gitignore` 排除本地配置和密钥文件；
- 错误响应不返回堆栈或凭据；
- 未知政策进入人工复核，不用模型猜测；
- 主观题、内容生成、讲解和生涯规划交给对应专业 Agent；
- 当前参考仓库不采集学习规划之外的个人信息。

# 架构说明

## 设计边界

系统遵循“LLM 理解和解释，确定性工具处理事实与计算”的边界。模型不能发布政策事实、计算掌握度、决定选科合法性或覆盖计划版本。模型不可用时，图流程继续走结构化表单和规则服务。

首次规划图：

```text
AgentRequest
  → 请求分派
  → 政策解析与校验
  → 目标解析/追问
  → 知识证据与画像
  → 时间容量与预算
  → 任务生成与排期
  → 四类发布校验
  → 等待用户确认
  → 新版本正式发布
```

四类发布校验包括政策与选科、知识覆盖与前置、时间容量与缓冲、内容资源与完成标准。任一硬约束失败时，计划停留在草稿或进入人工复核。

## 多智能体协作

```text
CollaborationRequest
  → DAG 与循环依赖校验
  → 根据角色或意图路由
  → 同一依赖层受控并发执行
  → 消息总线记录命令与结果
  → 统一结果聚合与证据去重
  → 乐观并发同步全局状态
  → CollaborationResponse
```

新增 Agent 只需：

1. 继承 `BaseEducationAgent`；
2. 声明 `AgentMetadata`、能力和意图；
3. 实现 `ainvoke(AgentRequest) -> AgentResponse`；
4. 注册到 `AgentRegistry`。

调度器没有固定 Agent 数量上限，测试使用 7 个 Agent 验证接入无需改动调度框架。

## 状态与版本

- 所有 Agent 和工具消息携带请求、追踪、学生、操作者和数据版本；
- 写操作使用幂等键；
- 计划确认或调整总是创建新版本；
- `GlobalStateStore` 使用 compare-and-swap 防止协作结果丢失更新；
- 消息总线保留按 trace 查询的不可变消息副本；
- 内存仓库是参考适配器，生产部署应替换为事务数据库和持久事件总线，接口无需修改。

## 安全和隐私

- Pydantic 信任边界拒绝未知字段；
- 密钥只从环境变量读取，`.gitignore` 排除本地配置和密钥文件；
- 错误响应不返回堆栈或凭据；
- 未知政策进入人工复核，不用模型猜测；
- 主观题、内容生成、讲解和生涯规划交给对应专业 Agent；
- 当前参考仓库不采集学习规划之外的个人信息。

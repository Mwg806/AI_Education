# 教师备课 Agent（Agent 04）

本模块依据《教师备课Agent工程设计说明书_优化版》实现。它是教师在环的备课协作 Agent，不替代教师作教学决定，也不会自动发布生成内容。

## 输入与知识依据

- 教师必须通过 MySQL 会话鉴权，并且只能使用自己所属班级；
- 班级学情在进入生成链前转换为匿名聚合统计，不传递学生姓名、账号或原始作答；
- 知识库读取 `Knowledge/teacher/高中九科优秀教案汇编_v3_化学生物政治升级版` 中的目录、27 份 PDF 和 SHA256 清单；
- 每个生成方案保留资源标题、机构、来源定位、版权状态和校验结果；
- 当前覆盖高中语文、数学、英语、物理、化学、生物、思想政治、历史和地理九科，每科 3 份参考材料。

## 生成结果与质量门禁

每个版本包含教学上下文、目标、重点难点、课堂活动时间线、板书、课堂检测与作业、动态分层、应急路径、来源列表和目标—活动—评价一致性矩阵。

发布前必须满足：

1. 每个教学目标都映射到活动、板书证据、评价任务和来源；
2. 活动总时长不超过总课时减去课堂缓冲；
3. 参考资源来源可追溯且通过完整性检查；
4. 实验课必须提供可用设备或安全条件；
5. 教师显式批准后才能显式发布。

LLM 可用时走结构化生成；不可用或调用失败时，系统返回 `reference_template` 模式的最小可用草稿，并显示 `TEACHING_LLM_UNAVAILABLE` 提醒，不把降级内容伪装成模型结果。

## 状态与版本

`teacher_review -> approved -> published -> feedback_recorded`

- 新建、修订、批准、发布和反馈都会生成不可覆盖的新版本；
- 修订请求支持 objectives、activities、board、assessments、differentiation 或 full；
- 教师可以锁定目标、活动、板书或评价组件，后续生成不得改写锁定内容；
- 只有 `published` 版本可以记录课后反馈；
- 发布动作产生 assessment 与 homework 两类标准事件，分别发送给学情诊断和作业辅导 Agent。

## MySQL

- `teacher_lesson_plans`：教案主记录、所属教师/班级、当前版本与状态；
- `teacher_lesson_plan_versions`：每个不可变版本的完整 JSON、锁定项和批准/发布时间；
- `teacher_lesson_feedback`：课后用时、检测表现、评分与教师复盘。

迁移由服务启动时的 `CREATE TABLE IF NOT EXISTS` 幂等执行，不删除已有数据。

## 教师端

教师登录后选择“智能备课”，可以完成：

1. 选择班级、学科、课型、课题、课时、教材和设备；
2. 检索匹配的优秀教案并生成可审核初稿；
3. 查看质量门禁、完整课堂流程、板书、分层、评价、对齐矩阵与来源；
4. 锁定组件、提交局部修订并查看版本变化；
5. 批准后发布，授课后记录课堂反馈。

## 验证

`tests/test_teacher_preparation_agent.py` 覆盖九科资源完整性、化学检索、匿名学情、课时与对齐门禁、锁定修订、批准/发布状态机、跨 Agent 发布事件、课后反馈版本及学生角色拒绝。项目同时执行全量 `pytest -q` 和 `npm run build`。
